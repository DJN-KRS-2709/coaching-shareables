01 Positioning Fork
The strategic question that has to land before pricing makes sense. Three live options: Standalone, pure Halo, or Hybrid (tier base + outcome upside). Click to choose. Coach's bet: Path C — it threads the PE test ("can it be priced on outcomes?") without losing the halo logic.
Path A
Standalone Monetized Product
What's sold: The agent itself, as a discrete SKU
Pricing model: Hybrid (modular base + outcome upside)
Strategy: Maximize — premium price justified by savings outcome
Recoupment: Direct agent revenue: N customers × $X/mo × Y months
Sales motion: Standalone deal cycle. Own buyer, demo, ROI conversation
PE test: ✓ Passes — outcome-priced
Risk: Light usage + lag-to-savings makes price hard to defend on direct value
When it fits: Daily/weekly use cases, measurable savings within a quarter, defined buyer
Path B
Pure Platform Halo
What's sold: The platform. Agent is included in premium tier
Pricing model: "Comes with Enterprise tier" — no separate price tag
Strategy: Tier-up — Enterprise becomes more attractive; existing customers upgrade
Recoupment: Incremental platform deals + ACV expansion per deal
Sales motion: Agent is the demo lead. The demo sells the platform
PE test: ⚠ Fails as framed — needs outcome reframe (e.g., "outcome = tier upgrades won")
When it fits: Episodic use, leadership-layer value, broader platform is the engine
Path C · Coach's Bet
Hybrid: Tier Base + Outcome Upside
What's sold: Agent included in Enterprise tier and outcome upside on validated savings
Pricing model: Tier uplift covers COGS + base margin · 5–10% of validated standardization savings above a threshold
Strategy: Maximize — leadership buyer pays the tier; ops user pays the outcome
Recoupment: Tier upgrades + outcome upside on heaviest-savings customers (closes payback gap)
Sales motion: Demo sells the platform. Outcome upside is the value-share story for the operations buyer
PE test: ✓ Passes cleanly — outcome component is real, not framed
When it fits: Two distinct buyers (leadership + ops), savings story is real but adoption pace is uncertain
Why Path C threads the needle: The PE test is explicit — "Can this product be priced on outcomes? YES → build an agent. NO → bolt it in as a feature." Path B as we framed it Saturday fails this test. Path C keeps the demo-sells-the-platform halo logic but adds the outcome component the framework demands. The boss can tell the board: "Tier-included for the leadership-team buyer. Outcome upside on validated savings for the ops team that drives the value. Both economics work; both buyers are aligned."
